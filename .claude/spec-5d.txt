## 1. 目标与范围

### 1.1 产品目标（为什么做 5D）

在 Step 5A–5C 之后，服务端已经能把已审批的 `DemoPlan` 录制成真实片段，并与旁白、SRT、Remotion 动效合成为可交付的 MP4 交付包。但目前仍存在三个高风险缺口：

1. **生产者自证**：当前只有 `browser-worker` 和 `render-worker` 各自声称“已完成”，缺少一个**独立于录制与渲染步骤的 QA 门禁**对黑屏、静帧、音画同步、声明资格与产物一致性做二次复核。
2. **AC-07 隐私缺口**：5C 仅在 `DemoPlan` Schema 层禁用了敏感 `fixtures` 键名，**从未扫描真实录屏帧、断言截图、`trace.zip` 网络/DOM 轨迹、SRT 或成片帧**。一旦演示页面中意外露出真实邮箱、GitHub PAT、Bearer Token、JWT 或 API Key，会被直接渲染进 MP4 甚至导出交付。
3. **Gate 3 无法定位问题与证据**：审核页目前仍主要依赖浏览器本地模拟的 `buildReviewBundle`，`ReviewArtifactPanel` 只拉取 `succeeded` 运行的 MP4；当服务端 QA 拦截某次运行时，审核员既看不到阻断原因，也无法定位到具体镜头、时间点、证据帧或 Trace 条目。

### 1.2 三大核心交付

1. **独立的录屏 / 成片 QA 步骤**：在服务端编排 DAG 中新增两个显式独立步骤——`qa_capture`（录屏后置、TTS/渲染前置，早拦截省成本）与 `qa_final`（渲染后置、`register_artifacts` 前置，覆盖技术/事实/隐私/内容四维全量复核），产出绑定全部产物哈希的 `QaReportV1`。
2. **AC-07 隐私扫描与硬阻断**：对录屏抽帧、成片逐镜抽帧、断言截图 PNG、Playwright `trace.zip`（DOM/网络/请求头/HTML/JSON/去重截屏帧）、SRT 字幕、镜头文案与 `demo-plan.json` 值执行邮箱 / Token / 密钥 / 私钥 / 敏感证件号扫描；命中即阻断运行与 Gate 3 导出，且**报告/日志/UI 严禁明文回显敏感原值**。
3. **审核页 Gate 3 定位级 QA 报告展示与导出硬门禁**：无论最新运行成功还是被 QA 阻断，Gate 3 审核页都能加载最新 `QaReportV1`，按镜头分组定位问题与证据（时间点、步骤 ID、Trace 路径、脱敏片段、服务端打码证据帧内联预览、一键跳编辑器对应镜头），并在服务端 `POST /exports` 与前端「批准视频」按钮双端强制阻断。

### 1.3 明确不做（5D 严格边界）

以下事项**严禁在本切片中顺手实现**，避免范围失控与回归：

- **不做 LLM 质量打分或视觉大模型审核**（[docs/07 §9](07-VIDEO-CAPTURE-RENDER-AND-EDITOR.md) 明确要求规则/媒体检测优先，不能用 LLM 评分替代确定性门禁；LLM 能力留待 5E）。
- **不做自动视频打码重编码替换原片**（AC-07 在 5D 的闭环是「精准扫描 → 证据帧打码展示 → 阻断发布 → 引导脱敏数据重录/编辑」；自动追踪区域打码渲染留待后续）。
- **不做增量 / 局部重渲染**（留待 5F）。
- **不改动 `libs/render`、`workers/render-worker`、`libs/state/src/studio-store.ts` 模拟生产链路**。
- **不改动 Step 2 资产**（`workers/browser-worker/plans/web-studio-tour.yaml` 的断言与既有页面文案逐字节保持不变）。
- **不引入用户登录、多租户鉴权或云对象存储**。


**为什么必须拆成 `qa_capture` + `qa_final` 两步而非仅在末尾做 1 步？**
1. **早拦截止损**：若真实录屏的 `trace.zip`、截图或录屏帧已出现真实邮箱/token，`qa_capture` 在 `synthesize_voice`（可能产生外部 TTS 费用）和 `render_video`（Remotion 耗时 1–3 分钟）之前立即阻断，且泄密片段永远不会被渲染进成片。
2. **全场景兜底**：当 `capture.enabled = false` 时（如仅用已有真实录屏资产或动效出片），`qa_capture` 创建即标 `skipped`（与 `plan_demo`/`capture_demo` 保持完全一致的零回归语义），而 `qa_final` **对每一次运行必跑**，统一检查成片 MP4 抽帧、已引用的既有真实录屏素材、SRT、镜头文案、黑屏/静帧、音画同步与 Claim 资格。

### 3.3 端口抽象（解耦编排器、OCR 引擎与测试双桩）

参考 5B `SpeechPort` 与 5C `CaptureJobExecutorPort`，在 `libs/ports/src/qa.ts` 定义两个端口：

1. **`ImageOcrPort`**：单张 PNG 图像文本提取接口
   - `isConfigured(): boolean`
   - `health(): QaOcrHealth`（`{ provider, configured, language }`）
   - `extractText(imagePath: string, options?: { signal?: AbortSignal; timeoutMs?: number }): Promise<OcrExtractionResult>`
   - 三种实现（位于 `apps/api/src/qa/`）：
     - `TesseractCliOcrAdapter`（默认生产实现）：`spawn('tesseract', [imagePath, 'stdout', '-l', lang, '--psm', '6'], { shell: false, windowsHide: true })`，零 npm 体积膨胀、零网络访问、单帧 1080p 约 150–350ms。
     - `DeterministicTestOcrAdapter`（离线测试实现）：优先读取同路径旁路文件 `<imagePath>.ocr.txt` 或按注入的 fixture 映射表返回确定性文本，无旁路文件时返回空文本。`synthetic: true` 会在 `QaReportV1.coverage` 中明确标注「测试 OCR」，绝不冒充真实 OCR。
     - `UnconfiguredOcrAdapter`：`isConfigured() === false`，调用 `extractText` 直接抛出 `QaOcrUnavailableError`（触发 fail-closed）。
2. **`QaRunnerPort`**：独立 QA 执行端口
   - `runCaptureQa(input: CaptureQaInput, callbacks?: QaRunnerCallbacks): Promise<QaRunOutcome>`
   - `runFinalQa(input: FinalQaInput, callbacks?: QaRunnerCallbacks): Promise<QaRunOutcome>`
   - `health(): QaHealth`
   - `abort(): void`（中止进行中的 `ffmpeg`/`ffprobe`/`tesseract` 子进程，支撑 `Orchestrator.cancelRun` 与 `stop()`）
   - `isRunning(): boolean`

### 5.1 敏感信息扫描引擎（`privacy-scanner.ts` · AC-07）

- `redactMatch(ruleId, raw)` 必须保证**任何规则都不保留超过 4 个前缀字符 + 4 个后缀字符**，且若原串长度 ≤ 8 则整体替换为 `[REDACTED]`。
- `scanText(text, context)` 内部立刻丢弃 `raw` 字符串，只向上游返回 `{ ruleId, matchRedacted, matchSha256 }`。单元测试必须断言：序列化后的 `QaReportV1` JSON 字符串**绝不包含**测试注入的原始邮箱、原始 token 或原始密钥！

### 5.2 Playwright `trace.zip` 安全解析与扫描（`zip-reader.ts` + `trace-scanner.ts`）

#### 安全 ZIP 读取器（`zip-reader.ts`）
使用 Node 内置 `node:zlib`（`inflateRawSync`）实现纯 TS ZIP 读取器（支持 Method 0 Stored 与 Method 8 Deflate，覆盖 100% Playwright `trace.zip`），无需新增原生或第三方依赖，且必须内置四重安全上限：
- `maxEntries`: `2000`
- `maxEntryUncompressedBytes`: `10 * 1024 * 1024`（10 MB）
- `maxTotalUncompressedBytes`: `100 * 1024 * 1024`（100 MB）
- 路径规范化检查：拒绝包含 `..`、绝对路径或空字节的条目名；任一超限均抛出结构化安全异常（不崩溃 API 进程）。

#### Trace 精确扫描策略与降噪（关键避坑点！）
Playwright `trace.zip` 包含 `vite preview` 提供的第三方前端打包 JS/CSS，**严禁无差别扫描全部条目**，否则第三方库的 license 邮箱或混淆代码会引发大量误报。必须按以下精确分层扫描：

1. **`*.trace`（NDJSON）**：逐行解析事件：
   - 动作事件（`before`/`action`）：检查 `params.url`、`params.value`（表单输入值）、`params.text`、`title`、`apiName`；并建立时间区间索引 `[startTime, endTime] → stepId/actionName`。
   - DOM 快照事件（`frame-snapshot`）：提取 `snapshot.html` 中的文本节点与 `input`/`textarea` 的 `value` 属性值，送入 `privacy-scanner`。
   - `console` / `error` 事件：扫描日志文本与错误消息。
   - `screencast-frame` 事件：收集引用的 `resources/<sha1>.jpeg`，按哈希去重后取代表帧（受 `maxTraceFrames` 限制，默认 12 帧，均匀抽样）送入 `ImageOcrPort`。
2. **`*.network`（NDJSON）**：逐行解析每个 HTTP `resourceSnapshot`：
   - **必扫**：`request.url`（含 query string）、`request.headers`（重点 `authorization`、`cookie`、`x-api-key`、`x-auth-token`）、`request.postData.text`、`response.headers`（重点 `set-cookie`）。
   - **响应体筛选**：依据 `response.content.mimeType` 决定是否扫描 `resources/<_sha1>`：
     - **扫描白名单**：`text/html`、`application/json`、`text/plain`、`application/xml`、`text/xml`、`image/svg+xml`。
     - **明确跳过（记入 `coverage.skippedTraceStaticEntries`）**：`application/javascript`、`text/javascript`、`text/css`、`font/*`、`application/wasm`、`video/*`、`audio/*`。
3. **定位映射**：每条来自 `trace.zip` 的 Finding 必须携带 `traceEntryPath`（如 `trace.network#14 (request.headers.authorization)` 或 `trace.trace#82 (snapshot)`）、对应的 `artifactId`（`capture_trace`）、按时间戳关联的 `stepId`、以及引用该 `captureAssetId` 的 `sceneId` / `sceneOrder`。

### 5.3 视频抽帧、OCR 与打码证据帧（`frame-extractor.ts` + `ocr-adapters.ts`）

#### 确定性抽帧策略（全部经 `ffmpeg` async `spawn`，`shell: false`）
1. **`qa_capture` 阶段（扫描 `capture_clip` MP4 + 断言截图 PNG）**：
   - 全部 `capture/screenshots/*.png` **逐张必扫**（同时解析 PNG `tEXt` / `iTXt` / `zTXt` 文本元数据 chunk，防隐写泄露！），通过 `capture-receipt.json` 的 `steps[].screenshot` 绑定 `stepId` 与 `startedAtMs`。
   - 对 `capture_clip` MP4 按 `1 fps`（`ffmpeg -i <clip> -vf fps=1 ...`）+ 首帧 + 尾帧抽帧，上限 `maxFrames`（默认 30 帧，超长片段等间隔自适应步长）。
2. **`qa_final` 阶段（扫描最终成片 `video_mp4`）**：
   - 按冻结 `input.json` 中每个镜头的帧区间 `[startMs, endMs]`：
     - 非 `real_demo` 镜头（`title` / `motion` / `cta` / `generated`）：每镜固定抽取 3 帧（15% / 50% / 85% 位置）。
     - `real_demo` 镜头：每秒 1 帧（或受 `maxFrames` 上限等间隔覆盖，默认总上限 60 帧）。
   - 若该运行跳过了 `qa_capture`（例如 `capture.enabled = false` 但工作区引用了已有 `Asset.mock === false` 的真实录屏），`qa_final` 还要扫描该真实素材指向的 `captureReceiptRef` 对应的截图与 `trace.zip`（若存在）。
3. **帧去重与清理**：对抽出的 PNG 计算 SHA256，相同帧只跑一次 OCR；QA 步骤结束后删除 `qa/frames-tmp/`，只把命中 Finding 的帧转存到 `qa/evidence/<findingId>.png`。

#### 隐私证据帧打码策略（防止「展示证据导致二次泄密」）
- 当某帧/截图命中**隐私规则**（`category === 'privacy'`）时：
  - 使用 `ffmpeg` 将该 PNG 渲染为**脱敏警示证据帧**（对主体内容施加 `boxblur=18:3` 强模糊，并在底部叠加半透明警示栏或边框，如 `drawbox=x=0:y=0:w=iw:h=ih:color=red@0.8:t=8`；注意不依赖外部字体文件，仅用 `boxblur` + `drawbox` 滤镜即可跨 Windows/Linux 100% 稳定运行！）。
  - 将脱敏后的 PNG 落盘为 `qa/evidence/<findingId>.png`，登记为 `qa_evidence_frame` 产物，并在 `Finding.location.evidenceFrameArtifactId` 中引用。
  - **原图绝不作为 `qa_evidence_frame` 暴露给前端内联预览**。
- 当某帧命中**技术异常**（如黑屏 `technical.black_frame`、静帧 `technical.freeze_frame`）时：
  - 直接将该时刻截取的 PNG（可叠加红色边框 `drawbox`）落盘为 `qa/evidence/<findingId>.png`，供审核员直观确认黑屏/卡死现场。

### 5.4 技术 / 事实 / 内容 QA 检查器

#### 技术 QA（`media-qa.ts`）
全部在 `qa_capture`（针对 `capture_clip`）和 `qa_final`（针对最终 `video_mp4` + `subtitles.srt` + `manifest.json`）独立重跑，**不信任 worker 上报的 JSON 字段**：

1. **`technical.video_decodable`（blocker）**：`ffmpeg -v error -i <file> -f null -`，退出码非 0 或 stderr 非空即阻断。
2. **`technical.probe_mismatch`（blocker）**：独立执行 `ffprobe` 复核 `h264`、16:9 尺寸、`fps`（容差 0.05）、`durationMs`（容差 250ms）、`frameCount` 以及磁盘文件 SHA256 与 `manifest.json`/`receipt.json` 一致。
3. **`technical.black_frame`**：执行 `ffmpeg -i <file> -vf blackdetect=d=0.3:pix_th=0.10 -f null -`，解析 stderr 中每条 `black_start:X black_end:Y black_duration:Z`：
   - 单段连续黑屏 `>= ASVS_QA_BLACK_BLOCK_MS`（默认 `1000ms`）或累计覆盖某镜头 ≥ 50% 时长 → **`blocker`**；
   - `300ms <= duration < 1000ms` → **`warning`**；
   - 按 `scene-mapper.ts` 精确映射到对应 `sceneId` / `sceneOrder`，并在 `(black_start + black_end) / 2` 截取证据帧登记为 `qa_evidence_frame`。
4. **`technical.freeze_frame`**（**仅作用于 `capture_clip` 及 `real_demo` 镜头区间**，避免对 `title`/`cta` 静态动效板误报）：
   - 执行 `ffmpeg -i <clip> -vf freezedetect=n=-60dB:d=3 -f null -`，解析 `freeze_start` / `freeze_end` / `freeze_duration`；
   - 静帧持续 `>= ASVS_QA_FREEZE_BLOCK_MS`（默认 `6000ms` 或占片段总长 ≥ 80%）→ **`blocker`**；
   - `>= 3000ms` → **`warning`**；截取中点证据帧。
5. **`technical.audio_sync_and_level`（blocker/warning，启用旁白时必检）**：
   - `ffprobe` 确认存在 `aac` 音轨、采样率 ≥ 22050Hz、1–2 声道、音画时长差 ≤ 500ms；
   - `ffmpeg -af volumedetect` 确认 `mean_volume > -90 dB`（静音判 `blocker`）；若 `max_volume >= -0.1 dB` 产出爆音削波 `warning`。
6. **`technical.subtitle_valid`（blocker，启用旁白时必检）**：
   - 重新读取磁盘 `subtitles.srt`，校验 SHA256 与 `manifest.subtitles.sha256` 一致，并调用 `@asvs/domain` 的 `parseAndValidateSrt(onDisk, { totalDurationMs })`。

#### 事实 QA（`fact-content-qa.ts`）
1. **`fact.claim_eligibility`**：
   - 从最新工作区快照读取当前视频引用的所有 `Claim` / `Feature`，逐条按所属 `sceneId` 复检：
     - 调用 `evaluateClaimGate`：`blocked_unverified`（AC-03）/ `blocked_stale`（AC-09）/ `blocked_rejected` → **`blocker`**（定位到引用该 Claim 的每一个具体 `sceneId`！）。
     - `needs_qualification`：检查对应镜头文案是否命中夸大词（`已上线|全面上线|现已上线|正式上线|全量可用|已全量开放`）→ **`blocker`**；是否缺少限定词 → **`blocker`**；已包含限定词 → **`warning`**（提醒审核员确认范围表述）。
2. **`fact.capture_provenance`**：
   - 遍历冻结分镜中所有 `real_demo` 镜头：
     - 若 `asset.mock === true`（占位素材）→ 产出 **`warning`**（诚实提示该镜头仍为占位画面，尚未接入真实录屏）。
     - 若 `asset.mock === false`（真实录屏）→ 独立复核 `capture-receipt.json`（`assertions.total >= 1 && assertions.failed === 0`）、磁盘 clip SHA256、`orchestration_approvals` 审批台账的 `approvedPlanDigest`（若本次运行含 Gate 2）以及 `manifest.json` 的素材哈希；任一不一致 → **`blocker`**。

#### 内容与品牌 QA（`fact-content-qa.ts`）
1. **`content.banned_phrase`（blocker）**：逐镜扫描 `title`/`narration`/`caption`/`notes` 是否包含 `video.brief.bannedPhrases`，精准定位到每个违规镜头。
2. **`content.narration_and_caption`**：启用旁白但某镜旁白为空 → **`blocker`**；字幕为空 → **`warning`**。
3. **`content.synthetic_voice_notice`（info/warning）**：若 `manifest.narration.synthetic === true`，写入一条 `info` 提醒「当前使用测试合成音轨，非真人商用配音」，与 5B 诚实标注保持一致。
4. **`content.brand_kit`（warning）**：缺少品牌字标或 CTA 时输出提醒。

### 5.5 镜头时间轴反查算法（`scene-mapper.ts`）

```ts
export interface SceneTimelineWindow {
  sceneId: string;
  sceneOrder: number;
  sceneTitle: string;
  visualType: string;
  assetId?: string;
  startMs: number;
  endMs: number;
  startFrame: number;
  endFrame: number;
}
```

- 直接消费冻结 `input.json` 中 `storyboard.scenes`（按 `order` 排序）与 `storyboard.fps`：
  - `startFrame` 累加每个镜头的 `durationFrames`（经 5B `synthesize_voice` 延展后的最终冻结帧数！）
  - `startMs = Math.round((startFrame / fps) * 1000)`，`endMs = Math.round((endFrame / fps) * 1000)`
- `mapTimestampToScene(windows, timestampMs)` 返回满足 `startMs <= timestampMs < endMs` 的镜头（末尾边界钳位到最后一镜）。
- `mapCaptureAssetToScenes(windows, assetId)` 返回引用该录屏 `assetId` 的所有 `real_demo` 镜头（用于把 `qa_capture` 阶段的截图/录屏帧/trace 问题同时关联到对应的分镜 `sceneId` 与 `sceneOrder`！）。

## 6. 编排器、API 路由与 Gate 3 强制门禁

### 6.1 `Orchestrator` 改造要点（`apps/api/src/orchestration/orchestrator.ts`）

1. **构造函数依赖注入**：`OrchestratorOptions` 新增 `qaRunner?: QaRunnerPort | null`、`qaReportStore?: QaReportStore | null`。
2. **`createRun` 零回归**：
   - 当 `capture.enabled === false` 时，`markCaptureStepsSkipped` 将 `['plan_demo', 'capture_demo', 'qa_capture']` 一并标为 `skipped`（`qa_final` 保持 `pending`，必跑）。
3. **`backfillCapture` 补登 `trace.zip`**：
   - 在 `registerCaptureArtifacts` 列表中新增 `capture_trace`（指向 `<outDir>/trace.zip`，`mimeType: 'application/zip'`），保证成功录屏的 trace 与截图/片段一起受控管理并供 `qa_capture` 扫描与溯源。
4. **`executeInlineStep` 新增两个分支**：
   - **`case 'qa_capture'`**：
     - 读取 `capture-receipt.json`、`demo-plan.json`、`input.json` 与 `orchestration_artifacts` 中本次运行的 `capture_clip`/`capture_screenshot`/`capture_trace`。
     - 调用 `qaRunner.runCaptureQa(...)`，将报告落盘 `<runDir>/qa/qa-capture-report.json`，登记 `qa_report` 与全部 `qa_evidence_frame` 产物，写入 `qa_reports` 表并更新 `run.qaSummary`。
     - 若 `report.verdict === 'fail'`：按最高优先级阻断类别映射错误码（`privacyBlockerCount > 0` → `qa_privacy_blocked`，若存在 `privacy.ocr_unavailable` → `qa_ocr_unavailable`，否则 `qa_technical_blocked`），抛出 `new StepFailure(code, summaryMessage, false)`（终态失败，不进入 `prepare_media`/`synthesize_voice`/`render_video`）。
   - **`case 'qa_final'`**：
     - 读取 `artifacts/<runId>.mp4`、`artifacts/manifest.json`、`artifacts/receipt.json`、`subtitles.srt`（若有）、`input.json`、最新工作区快照与 `qa_capture` 报告（若有）。
     - 调用 `qaRunner.runFinalQa(...)`，将报告落盘 `<runDir>/qa/qa-final-report.json`，登记 `qa_report` 与 `qa_evidence_frame`，写入 `qa_reports` 表并更新 `run.qaSummary`。
     - 若 `report.verdict === 'fail'`：抛出对应 `StepFailure`（`qa_privacy_blocked` / `qa_ocr_unavailable` / `qa_technical_blocked` / `qa_fact_blocked` / `qa_content_blocked`，`retryable: false`），**阻止进入 `register_artifacts`**（因此不会暴露可交付 `video_mp4`，也不会令 `run.status = 'succeeded'`）。
5. **`cancelRun` 与 `stop()`**：同步调用 `this.qaRunner?.abort()`，确保中止正在运行的 `ffmpeg`/`tesseract` 子进程。
6. **`createExportBundle` 第 5 项硬门禁（Gate 3 服务端防绕过）**：
   在校验完 `video_mp4` / `subtitles_srt` / `render_manifest` / `artifact_receipt` 哈希之后、落库 `export_bundles` 之前，强制校验：
   1. `qaReportStore.getByRun(workspaceId, run.id, 'final')` 存在，且 `orchestration_artifacts` 中存在对应的 `qa_report` 产物；否则 `409 export_qa_missing`。
   2. 调用 `rehashArtifact(workspaceId, qaReportArtifact)` 复算磁盘 `qa-final-report.json` SHA256，与 DB 与 `qa_reports.report_sha256` 逐字节一致；否则 `409 export_hash_mismatch`。
   3. 用 `qaReportV1Schema.parse` 复读磁盘报告，校验：
      - `report.verdict !== 'fail'` 且 `report.summary.blockerCount === 0` 且 `report.summary.privacyBlockerCount === 0`；否则 `409 export_qa_blocked`（`details` 带阻断列表摘要，不含敏感原文）。
      - `report.subject.mp4Sha256 === verified.video_mp4.sha256`、`report.subject.manifestSha256 === verified.render_manifest.sha256`、且有字幕时 `report.subject.srtSha256 === verified.subtitles_srt.sha256`；否则 `409 export_qa_stale`。
   4. 将 `qa_report` 加入交付包 `files` 数组（文件名 `${video.id}.qa-report.json`），并在 `ExportBundleV1` 中记录 `qaReportArtifactId` 与 `qaReportSha256`。

### 7.2 审核页 Gate 3 交互与信息架构

#### 数据加载与 Gate 3 联动（`review-page.tsx` + `review-artifact-panel.tsx`）
1. 在 `ReviewPage` 中（当 `syncConfig.enabled` 时），拉取 `client.getLatestQaReport(workspaceId, videoId)`（**独立于 `getLatestVideoArtifact`**，这样即使最新运行在 `qa_capture` 或 `qa_final` 失败、没有新 MP4，Gate 3 依然展示这份阻断报告！）。
2. 将服务端 QA 判定合并进 Gate 3 审批守门：
   - 定义 `serverQaBlocked`：`latestQa !== null && latestQa.report.verdict === 'fail'`。
   - 定义 `serverQaStale`：`latestQa !== null && latestQa.report.subject.scriptVersion !== video.scriptVersion`。
   - **当 `serverQaBlocked === true` 时**：
     - 顶部检查总览明确计入阻断（提示「服务端独立 QA 阻断：N 项阻断（含 M 项 AC-07 隐私守门）」）；

   - **当未连接服务端或该视频从未跑过服务端运行时**：
     - 保持诚实提示（「当前未连接服务端独立 QA，下方检查仅覆盖浏览器内文案模拟扫描，不含录屏帧/截图/trace 隐私扫描」），不破坏现有本地离线审核体验与既有 E2E 用例（`review.spec.ts`）。

#### `QaReportPanel` 展示结构（`libs/features/production-suite/src/qa-report-panel.tsx`）
1. **报告头与总览条**：
   - 判定徽章：`通过`（success）/ `通过 · 有提醒`（warn）/ `已阻断`（danger）

   - 扫描覆盖条：`录屏帧 X · 成片帧 Y · 截图 Z · Trace 条目 W · OCR: Tesseract / 测试 OCR`（测试 OCR 必带 `warn` 徽章）
   - 「下载 `qa-report.json`」按钮（经 `downloadVerifiedArtifact` 做 WebCrypto SHA256 校验后保存）
2. **四维状态摘要 + 筛选条**：

   - 筛选器：`全部` / `仅阻断` / `仅提醒` + 按维度切换。
3. **按镜头分组的问题定位列表（核心交付）**：
   - 先展示 `全局 / 成片级` 问题（若有），再按 `video.scenes` 顺序仅展开或高亮存在 Finding 的镜头（也可切「查看全部镜头」确认哪些镜头 0 问题）：

     - 单条 Finding 卡片：
       - 严重度徽章 + 维度标签 + 等宽 `ruleId`
       - 标题、说明与修复建议（`remediation`）
       - **精确定位元数据行**：时间点（`00:12.400` · 若有持续时长显示 `持续 1.4s`）、帧号、来源类型中文标签（`录屏帧`/`断言截图`/`Playwright Trace`/`成片帧`/`SRT 字幕`/`镜头文案`）、`stepId`、`traceEntryPath`、`claimId`
       - **脱敏证据块**：存在 `matchRedacted` 时以等宽危险/警告样式框展示掩码片段（例如 `命中样本（已脱敏）：ghp_****9a2f · SHA256 9f2c...`）
       - **可视化证据帧**：存在 `location.evidenceFrameArtifactId` 时，渲染内联缩略图 `<img src={client.artifactInlineUrl(ws, id)} />`（隐私命中帧旁显式标注「证据帧已服务端模糊脱敏」），点击可在 `@asvs/ui` `Dialog` 中放大查看，并提供校验下载按钮
       - **一键直达修复**：
         - `remediationAction === 'editor'` → `<Link to={`/videos/${video.id}/editor?scene=${finding.location.sceneId}`}>定位到第 N 镜</Link>`
         - `remediationAction === 'production'` → `<Link to={`/videos/${video.id}/production`}>去生产监控重录</Link>`
         - `remediationAction === 'knowledge'` → `<Link to={`/projects/${project.id}/knowledge`}>去知识中心核验</Link>`

## 9. 测试与验收标准（Exit Gate）

### 9.1 真实端到端验收脚本：`pnpm qa:verify`（必须真实执行，不 mock 核心扫描）

在 `apps/api/src/scripts/verify-qa-privacy.ts` 实现，使用真实 SQLite、真实 `ffmpeg`/`ffprobe`、真实 ZIP 解包、真实 `tesseract` OCR（通过 `ffmpeg` 将测试文本绘制或用 Playwright 渲染含敏感信息的真实 HTML 截图/视频帧！）与真实 `IndependentQaRunner`，至少验证以下 **18 项断言**：

| # | 场景 | 必须通过的断言 |
|---|---|---|
| 1 | 健康检查 | `GET /v1/health` 返回 `qa.enabled=true`、`qa.ocrProvider='tesseract_cli'`、`qa.ocrConfigured=true`、`qa.policyVersion='qa-v1'` |
| 2 | 正常真录屏 + 真渲染 | 干净录屏 + 旁白 + 渲染 → `qa_capture` 与 `qa_final` 均为 `succeeded`，`verdict` 为 `pass` 或 `pass_with_warnings`（0 blockers） |
| 3 | 成功态 Trace 登记与扫描 | 成功运行登记了 `capture_trace`，且 `qa_capture` 报告 `coverage.scannedTraceEntries > 0`、`scannedScreenshots > 0`、`scannedCaptureFrames > 0` |
| 4 | 正常 Gate 3 交付包 | 批准后 `POST /exports` 返回 `201`，交付包包含 `qa-report.json`，其 SHA256 与 `qa_reports` 及下载字节一致 |
| 5 | **AC-07 · Trace 隐私阻断** | 构造含 `Authorization: Bearer eyJ...` 与 `alice.secret@corp.internal` 的真实 `trace.zip` → `qa_capture` 失败 `qa_privacy_blocked`（`retryable=false`） |
| 6 | 早拦截止损验证 | 上述用例中 `synthesize_voice` 与 `render_video` 均为 `pending`（0 次 TTS 调用、0 个成片 MP4 文件） |
| 7 | **反向泄密零明文断言** | 读取磁盘 `qa-capture-report.json` 与 `GET /latest-qa-report` 响应全文，**不得出现**原始 Bearer Token 或原始邮箱，只出现 `matchRedacted` 与 `matchSha256` |
| 8 | **AC-07 · 截图 PNG 真实 OCR 阻断** | 使用真实 PNG（画面清晰渲染 `ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxx` 或 `ceo@acme-internal.io`）运行真实 `tesseract` OCR → `qa_capture` 命中并阻断 |
| 9 | **AC-07 · 录屏视频帧真实 OCR 阻断** | 使用真实 MP4 片段（某秒画面出现 `sk-proj-...` 或邮箱）→ `ffmpeg` 抽帧 + 真实 OCR 命中 → 精准定位 `timestampMs` 与对应 `sceneId` |
| 10 | 隐私证据帧脱敏验证 | 命中隐私的 `qa_evidence_frame` PNG 存在且可经 `?inline=1` 下载（含 `X-Content-Type-Options: nosniff`），其 SHA256 **不等于**原始未打码截图/帧（证明已做脱敏处理） |
| 11 | **AC-07 · 字幕/文案隐私阻断** | `capture.enabled=false` 时在某镜头字幕放入邮箱/密钥 → `qa_final` 命中 `scene_text` / `subtitle_srt` 并阻断，不登记 `video_mp4` |
| 12 | **技术 QA · 黑屏检测定位** | 构造第 2 镜含 1.5s 纯黑帧的真实 MP4 → `qa_final` 命中 `technical.black_frame`（`blocker`），精确定位到第 2 镜 `sceneId`、`timestampMs` 与黑屏证据帧 |
| 13 | **技术 QA · 录屏静帧检测** | 构造全程静止 7s 的 `capture_clip` MP4 → `qa_capture` 命中 `technical.freeze_frame` |
| 14 | **Fail-Closed · OCR 不可用** | `ASVS_QA_OCR_PROVIDER=unconfigured` 跑含真实录屏/成片帧的运行 → 必须阻断 `qa_ocr_unavailable`，绝不放行 `pass` |
| 15 | **Gate 3 接口可见失败报告** | `GET /videos/:videoId/latest-qa-report` 对被 QA 阻断的运行返回 `200` 及完整定位报告与证据帧列表 |
| 16 | **Gate 3 防绕过 1（QA 阻断）** | 即使视频在工作区被标记 `approved`，对 QA 失败的运行调 `POST /exports` 返回 `409`（`export_run_missing` 或 `export_qa_blocked`） |
| 17 | **Gate 3 防绕过 2（篡改报告）** | 篡改磁盘 `qa-final-report.json` 任意 1 字节 → `GET /qa-report` 返回 `409 qa_report_tampered`，`POST /exports` 返回 `409 export_hash_mismatch` |
| 18 | **5A/5B 零回归** | `capture.enabled=false`、`narration.enabled=false` 时 `plan_demo`/`capture_demo`/`qa_capture`/`synthesize_voice`/`generate_subtitles` 全部创建即 `skipped`，`qa_final` 正常执行并通过 |

### 9.2 Playwright 浏览器 E2E（`apps/web-studio/e2e/qa-gate3-real-flow.spec.ts`）

在 `e2e-fixture-api.ts` 扩展支持注入可控的 QA 通过 / AC-07 隐私阻断报告及测试 PNG 证据帧，至少覆盖 4 条浏览器用例：
1. **隐私阻断流（AC-07）**：运行在 `qa_capture` 命中邮箱/token 阻断 → 生产页显示失败并可跳转审核页 → 审核页 Gate 3 展示「独立 QA 报告（已阻断）」、定位到具体镜头卡片、显示脱敏片段（不含原文）、内联加载经 `nosniff` 保护的 `qa_evidence_frame` 缩略图、**「批准视频」与「生成交付包」按钮均处于禁用状态**。
2. **定位直达编辑流**：点击 QA 报告卡片中的「定位到第 N 镜」→ 跳转到 `/videos/:videoId/editor?scene=<sceneId>` 并自动选中对应镜头。
3. **通过与交付流**：QA 全部通过（含 1 条非阻断提醒）→ 审核页展示通过报告与覆盖统计 → 批准视频 → 生成交付包 → 交付包内可见 `qa-report.json` 并可完成 SHA256 校验下载。
4. **未连接服务端降级**：离线模式下审核页不崩溃，诚实提示当前未连接服务端独立 QA，本地模拟审核流程保持不变。

## 10. 关键风险与避坑指南

| 风险 | 表现与后果 | 必须落实的防线 |
|---|---|---|
| **初始 JS 突破 230 kB 预算** | 5C 仅余 0.7 kB；把 `qa.ts` Schema 或正则规则塞进静态导入链会直接让 CI `build` 变红 | 规则库仅放 `apps/api/src/qa/`；`QaReportPanel` 强制 `React.lazy`；`OrchestrationRunV1` 只挂极简 `qaSummary`；每次改前端必跑 `pnpm build && pnpm budget` |
| **Trace 扫描误报打包 JS** | `vite preview` 提供的 React/Lucide bundle 中可能含作者邮箱或关键字，导致正常录屏必挂 | `trace-scanner.ts` 严格按 `mimeType` 跳过 JS/CSS/font/wasm，只扫 `.trace`/`.network`/HTML/JSON/TXT/SVG 与去重截屏帧 |
| **QA 报告自身造成二次泄密** | 明文把抓到的 `ghp_...` 或未打码截图写进 JSON / DB / API / UI | 扫描器内部即刻脱敏 + 哈希，报告与日志单测做负向全文断言；隐私证据帧经 `ffmpeg boxblur+drawbox` 脱敏后再登记 `qa_evidence_frame` |
| **旧 5A/5B/5C 单测假 MP4 失败** | 旧单测写出 `'fake-mp4'` 文本字节，直接跑真 `ffprobe`/`ffmpeg` 会全部报错 | 编排器通过 `QaRunnerPort` 调用 QA；旧单测与 `e2e-fixture-api.ts` 注入轻量测试双桩，真实媒体/OCR 由 `qa:verify` / `gate2:verify` / `export:verify` 证明 |
| **Windows 与 Linux CI 路径/工具差异** | Windows 无预装 `tesseract` 或路径分隔符 `\` 导致 `storageRef` 校验失败 | 全部子进程使用 `spawn(..., { shell: false, windowsHide: true })`；`storageRef` 统一 POSIX `/`；CI 在 `validate`/`render`/`capture` 安装 `tesseract-ocr`；本地无 `tesseract` 时用 `ASVS_QA_OCR_PROVIDER=deterministic_test` 跑单测，真实录屏环境必须装 `tesseract`（否则 fail-closed 报错而非假绿） |
| **静态标题页误报静帧** | `title` / `cta` 镜头本来就会静止数秒，对整片跑 `freezedetect` 会疯狂误报 | `freezedetect` **仅**作用于 `capture_clip`（`qa_capture`）或 `real_demo` 镜头区间，绝不对整片无区分执行 |
| **临时抽帧打爆磁盘** | 每次跑 QA 抽几十张 1080p PNG 约数十 MB，反复运行堆积 | 抽帧写入 `qa/frames-tmp/`，在 `try/finally` 中强制清理，只保留命中 Finding 的少数 `qa/evidence/*.png` |
