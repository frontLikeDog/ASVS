# 02 · 完整产品需求文档（PRD）

> Draft v0.1｜范围：长期完整产品 + 首个可交付 MVP｜所有功能默认未实现。

## 1. 用户故事与任务

### US-01 项目接入
作为开发者，我可以创建工作区、连接只读 GitHub 仓库、指定分支/提交、导入 PRD/README、设置 staging URL，以便系统理解产品。允许不提供源码，仅使用文档、公开页面和授权演示环境。

**验收**：显示每个来源的连接状态、最后同步时间、授权范围、错误与撤销入口；失败不阻塞其他来源；不得明文保存凭证。

### US-02 功能发现
作为 PM，我能看到系统提议的功能目录、相关 PR/源码/文档、可用状态和证据等级，并能编辑/合并/驳回功能。

**验收**：每条功能有 source references；系统区分设计中、已实现、已验证、已部署、已公开；不从 PR 标题直接推断已发布。

### US-03 创建视频 Brief
作为市场人员，我选择宣传片/更新视频/教程/批量内容，填写受众、平台、时长、语言、品牌调性、功能范围和禁用表述。

**验收**：Brief 可保存草稿、修订和锁定；重要字段变更触发受影响分镜重新策划。

### US-04 AI 策划与审核
作为视频负责人，我能看到 Claim 候选、旁白、分镜、时长、素材来源、风险提示，并逐条批准或修改。

**验收**：每个事实性 Claim 有证据链接和核验状态；未经批准不得进入需要写操作的自动演示。

### US-05 自动演示
作为视频负责人，我授权 AI 在 staging 环境使用测试账号执行 DemoPlan、截图和录屏，并看到每步执行和断言。

**验收**：可限制域名、账号、操作、时间和资源；支持 dry-run、重试、环境重置、人工接管；任何生产写操作默认拒绝。

### US-06 分镜编辑
作为编辑，我能修改单个镜头的文字、录屏、裁切、焦点、配音、动效、时长、转场，预览并只重生成该镜头。

**验收**：编辑操作产生 Scene Revision；依赖未变的镜头不重复调用昂贵服务。

### US-07 导出
作为发布负责人，我选择 16:9/9:16/1:1、分辨率、字幕模式和语言，生成 MP4、SRT、封面、工程清单。

**验收**：输出校验可播放、音画时长、字幕时间轴、文件 hash、导出状态；发布前有最终审核。

### US-08 版本更新触发
作为 PM，合并 PR 或发布 Release 后，系统提出视频选题草稿，并列出用户可感知变更及不应宣传的内部变更。

**验收**：事件去重；不会自动公开发布；只有已授权项目会监听；能够追踪 PR 到发布版本的关联。

## 2. 功能模块与优先级

| 模块 | P0 首版 | P1 增强 | P2 后期 |
|---|---|---|---|
| Project Hub | 仓库/文档/staging 接入 | 多源同步、增量索引 | 企业连接器 |
| Knowledge | 功能候选、证据引用 | 依赖关系与过期传播 | 跨项目复用 |
| Director | Brief、Claim、分镜 | 多风格策略、A/B 文案 | 自动营销优化 |
| Demo | Playwright 录屏 | 自愈 locator、人工接管 | 桌面自动化 |
| Editor | 分镜编辑、基础预览 | 多轨时间线、局部重渲染 | 高级协作编辑 |
| Render | MP4、TTS、字幕 | 多语言、多比例 | 多格式批量导出 |
| Governance | 审批、审计、脱敏 | 企业权限、私有执行 | 合规策略模板 |
| Factory | 手动触发生产 | Release 触发草稿 | 审批后自动发布 |

## 3. 页面信息架构

1. **Workspace**：项目列表、成员、账单/额度、全局设置。
2. **Project Hub**：连接器、环境、知识快照、功能目录、同步记录。
3. **Feature Detail**：功能说明、Claim、Evidence、演示入口、变更历史。
4. **Video Library**：项目视频、草稿、模板、导出版本、状态。
5. **AI Director**：聊天式 Brief、策划建议、Claim 审核、分镜卡片。
6. **Demo Lab**：演示计划、步骤、浏览器回放、断言、失败截图。
7. **Video Editor**：预览、分镜、时间线、素材、属性、旁白和字幕。
8. **Production Monitor**：任务 DAG、Worker、日志、重试、审批、资源成本。
9. **Brand Kit**：Logo、字体引用、色板、片头片尾、语气、禁用词。
10. **Review & Export**：质量报告、审批、MP4/SRT/封面下载。

## 4. 关键用户流程与异常

### Flow A：PR → Release Video

1. 选择仓库和 PR/Release 范围；
2. 抽取 Diff、文档、测试与部署信息；
3. 生成“用户可感知变化”候选；
4. 识别 Claim 与证据缺口；
5. 用户批准 Brief/Claim；
6. 规划 DemoPlan 并验证环境；
7. 录屏、剪辑、独立 QA；
8. 用户审核、导出。

异常：PR 未合并、功能开关关闭、测试失败、环境不可达、录屏中断、素材泄密、渲染失败，均应明确阻断或降级；不得静默捏造成功。

### Flow B：无源码 → Guided Demo

输入 URL、测试账号（安全凭证引用）、功能目标和手工步骤；AI 提议操作路径，用户批准；执行录屏；用 UI 实际观察与用户提供的文档支撑 Claim。对无法验证的功能声明显示“待审核”。

### Flow C：Product Film

基于多个已验证功能选取 3–5 个卖点；规划开场、问题、功能演示、结果、CTA；真实录屏 + Remotion 品牌动效 + 可选概念视觉；导出不同平台比例。

## 5. 业务规则

- 产品声明不得仅由 LLM 自评通过；须依据证据及人工最终批准。
- “合并”不等于“部署”；“部署”不等于“对所有客户开放”。
- 视频中的数字化收益、性能提升需有可复现测量或授权客户证据。
- 不允许模型直接访问原始凭证；只传递最小权限的工具能力。
- 原始录屏与最终输出保留可追溯关联，支持删除与保留期限。
- 公开发布必须人工明确批准；第一版不内置自动发布。

## 6. 非功能需求

**可用性**：失败任务可见、可取消、可重试；至少在 Worker 崩溃后能从已持久化步骤恢复。  
**安全性**：租户隔离、最小权限、审计、SSRF 防护、域名白名单、脱敏。  
**性能**：首版建立测量基线；初始候选目标为本地小规模 PR 结构化分析 10 秒内（不含模型与网络），不作 SLA 承诺。  
**扩展性**：Browser/Render/Index Worker 独立扩缩容。  
**可维护性**：所有外部接口版本化，Nx project boundaries + CI enforced。  
**可观测性**：每个生产步骤关联 runId、sceneId、artifactId、traceId。

## 7. 验收用例

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-01 | 只读 GitHub 授权 | 能列 PR；不能写仓库 |
| AC-02 | PR 只有重构 | 不自动宣称新功能 |
| AC-03 | 已合并未部署 | 标记待验证，阻止“已上线”声明 |
| AC-04 | 浏览器步骤失败 | 保存错误、截图、trace；不生成虚假演示 |
| AC-05 | 单镜头改旁白 | 不重新录制其他镜头 |
| AC-06 | 渲染 Worker 中断 | 从 checkpoint 恢复或明确失败 |
| AC-07 | 敏感数据出现在录屏 | 审核阻断或要求遮挡重录 |
| AC-08 | 不提供源码 | 仍可创建手动/运行态演示视频 |
| AC-09 | 证据过期 | 相关 Claim 与 Scene 标记需复核 |
| AC-10 | 导出完成 | MP4 可播放，SRT 时间轴有效，hash 已记录 |

## 8. 不在 MVP 范围

完整多轨非线性编辑器、跨浏览器复杂自愈、原生移动 App 自动化、企业 SSO、自动公开发布、真实客户数据录屏、生成式视频镜头无限重试。
