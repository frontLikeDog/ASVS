# 01 · 产品愿景与战略定位

> 状态：Draft v0.1｜日期：2026-11-15｜产品代号：AI Software Video Studio（ASVS）  
> 文档性质：产品战略基线；非已验证市场事实。

## 1. 一句话定义

AI Software Video Studio 是一个**理解真实软件、验证功能、自动演示并制作可编辑产品视频**的 AI 原生工作室。它将软件产品的文档、代码、PR、发布记录、运行界面及测试证据转化为可追溯的产品知识，再将其编译为宣传片、版本更新视频、教程和销售演示。

**北极星目标：从可信的软件功能事实到可审阅、可重制、可发布的视频内容，形成可重复的自动化闭环。**

## 2. 为什么做

传统文生视频工具缺乏软件产品事实，容易生成不存在的 UI；屏幕录制工具能拍到真实画面，却不理解产品卖点；视频编辑器能剪辑，却不理解 PR 与版本变化。软件团队必须手工串联产品经理、工程师、录屏者、文案与剪辑师。

我们解决四个断层：

1. **知识断层**：从仓库、文档、运行环境提炼功能目录。
2. **事实断层**：每一条对外功能声明绑定证据、版本、环境和审核状态。
3. **视觉断层**：真实产品操作是功能展示的主要视觉来源，生成式视觉仅做辅助。
4. **生产断层**：镜头、素材、旁白、模板、版本可复用；局部修改只重做受影响部分。

## 3. 产品四大模式

| 模式 | 用户输入 | 主要输出 | 关键差异 |
|---|---|---|---|
| Product Film | 产品目标、受众、卖点、品牌 | 30–180 秒产品宣传片 | 真实 UI + 品牌叙事 |
| Release Video | PR / Commit / Release 范围 | 新功能更新视频 | 版本差异与可验证声明 |
| Guided Demo | 功能、操作目标、演示环境 | 操作教程、销售 Demo | 可执行演示计划和真实录屏 |
| Content Factory | 发布事件、品牌规则、渠道配置 | 多版本、多比例视频草稿 | 事件驱动、批量化、复用 |

四个模式共享 Project Intelligence、Claim/Evidence、Storyboard IR、Capture、Render、Review 基础设施，不允许分别复制一套数据模型和工作流。

## 4. 初始市场与 ICP

**第一批目标客户**：持续交付的 Web SaaS、AI SaaS、开发者工具团队，优先 5–100 人规模、已有 GitHub 工作流和可访问的测试环境。地域与商业化渠道在用户访谈后决定；中文界面和中文配音优先支持。

关键角色：独立开发者、产品经理、开发负责人、市场运营、客户成功、售前工程师。采购驱动：制作耗时、外包成本、版本更新频率、内容一致性、可审核性。

不把“用户愿意付费”“市场缺口巨大”当成已证实结论；需进行至少 10 次目标用户访谈和 3 个真实项目试点。

## 5. 差异化与不可妥协原则

- **真实优先**：真实功能画面优先于模型虚构画面；生成式 UI 不得冒充产品截图。
- **Claim-first**：每个对外产品声明必须可追溯到依据，并有发布审核。
- **可编辑**：输出结构化视频工程，不只输出一次性 MP4。
- **可恢复**：每个生产步骤有持久状态、幂等键、可重试边界。
- **最小权限**：不强制访问源码；允许仅通过文档与测试环境接入。
- **独立产品**：与 ATVG2 通过版本化协议适配，不把 ATVG2 作为运行必需依赖。

## 6. 非目标

首版不做通用影视生成平台、不做完整 Premiere 替代品、不支持任意桌面应用的无监督操作、不自动向公开平台发布、不保证每个仓库都能自动发现可演示功能、不直接执行陌生仓库任意构建脚本。

## 7. 北极星指标与质量指标

**北极星指标**：每周通过事实审核、可复用的视频草稿数量（Verified Reusable Video Drafts）。

辅助指标：

- 从批准 Brief 到可审核初稿的中位时间；
- 视频中已核验声明比例及无证据声明数量（目标：公开成片为零）；
- 自动演示成功率、失败恢复成功率；
- 镜头级局部重渲染命中率；
- 人工修改分钟数、每成片分钟成本；
- 导出成功率、播放质量与客户满意度。

以上指标需要基线测试，不预先宣称达成。

## 8. 商业化假设

可探索按工作区/席位订阅加生产额度计费；浏览器录屏、TTS、模型推理、渲染、生成式视频应分别计量成本。企业版可提供私有执行、审计和专有连接器。定价须基于实测成本和用户访谈，不在此文档固定。

## 9. 战略性产品决策

1. 完整 D 形态作为长期架构；从 Release Video 的真实 PR 闭环切入。
2. 前期 Web SaaS 优先；桌面应用录制推迟。
3. Node/TS 控制平面，原生媒体工具，按测量结果引入 Rust。
4. Nx + pnpm Monorepo；模块化单体控制平面 + 隔离执行 Worker。
5. 视频工程与产品知识快照独立版本化。

## 10. 待验证问题

- 目标客户更看重“漂亮宣传片”还是“持续更新视频”？
- 仅 UI 接入的用户能接受怎样的功能发现准确率？
- 自动录屏的稳定性在真实业务流程中能否达到可用门槛？
- 企业是否接受云端源码索引，还是要求私有执行？
- 一条 60 秒成片的平均人工干预和计算成本是多少？
